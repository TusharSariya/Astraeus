# Design

The worker calls `operation_bounds` before the payload-bearing discovery request. It verifies the measured 4096-byte target filesystem geometry and launches a zero-input child to prove locked `RLIMIT_AS` and `RLIMIT_FSIZE` support. Unsupported targets fail before network access.

The AWC response is streamed under a 64 KiB ceiling with identity transfer encoding and exact transport completion. The parent retains only those raw bytes, bounded headers, and the bounded child reply. Inspection and normalization run in a child with a 640 MiB address-space cap, 64 KiB stdin/stdout and single-file output caps, and 16 KiB stderr. Linux trials found 384 MiB fails during the required numeric-library/thread initialization while 512 MiB was insufficient in the full parent/replay environment and 640 MiB repeatedly succeeds; the limit is a locked virtual-address-space ceiling, not a total-memory claim. Every response row must identify CYYT, carry a unique integral finite observation time inside the requested window, and the complete response must contain at most 64 rows. Any violation refuses the whole response without filtering.

The maximum-row measurement used 64 records and produced a 36,923-byte ZIP occupying 40,960 physical bytes on the supported 4096-byte filesystem. The enforced 65,536-byte file ceiling is itself block aligned, so its maximum physical data allocation is 65,536 bytes; admission separately carries two simultaneously live 4096-byte directory allocations: the worker operation directory and the child private workspace. The private child output is atomically promoted, so there is one output inode rather than simultaneous source and destination copies. Existing destinations and all private workspaces survive or clean up according to the shared isolation contract.
